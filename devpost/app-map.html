agentlog — app map

A take-home guide to what was built, where it lives, and one practice to reuse. Companion to devpost/checklist.md; the canonical plan docs are scope.md, prd.md, spec.md.

The shape

open index.html → app.js boot: records = Store.load() (localStorage "agentlog.records") → render(): Insights · LogList · agent-name datalist submit "Log it" → validate ask + lesson → records.unshift(record) → Store.save() → render() (insights strip updates in the same instant) Export Markdown → Exporter.toMarkdown(records) → Blob download "agentlog-export.md" + clipboard copy (fallback hint if denied)

Where things live

Store — app.js › load() / save() / isWellFormed(). localStorage round-trip; corrupt data degrades to an empty log.
RecordForm — app.js › form submit handler. Validation, record shape, agent-name datalist learning.
Insights (the kernel) — app.js › computeInsights(records). Pure function: outcome counts + most frequent tag among failed records.
LogList — app.js › visibleRecords() / renderList(). Filter predicate (outcome pill + search) → newest-first cards.
Exporter — app.js › toMarkdown() + export click handler. Full log → Markdown file + clipboard.
Look — styles.css › :root custom properties. Bench-tool palette; outcome colors are the only decoration.

What the build verified

29/29 headless-Chromium checks in devpost/verify_app.py: form/render, persistence and corrupt-storage recovery on both http:// and file://, live insights, combined filters, real export download, empty/no-match states.

The practice to reuse

The spec's one open uncertainty — does localStorage/clipboard behave the same on file:// as on http://? — was settled not by reading docs but by a two-origin check in the very first slice. Practice: write your unknown into the plan as a question, then make the earliest slice answer it with evidence. It cost one extra page-open and removed a whole class of README guesswork.
